# 05. Mapa del curso (cómo se conecta el proyecto con tus clases)

Esta tabla te sirve como «mapa rápido» para mostrarle a la profesora exactamente qué temas de las semanas del curso aplicaste en el proyecto y en qué archivo está cada uno.

| Semana del curso | Tema visto en clase | Cómo se aplica en nuestro proyecto | Archivo principal |
|---|---|---|---|
| **Semana 02** | Sistemas autónomos y seguridad con supervisión humana en casos críticos | El chatbot opera localmente de forma autónoma, pero si detecta señales de suicidio o autolesión detiene la clasificación y deriva a ayuda humana real (**Línea 113 Salud del MINSA, Opción 5**). | `p04_seguridad.py` |
| **Semana 03** | Agentes inteligentes (sensores, procesador, actuadores, secuencia de percepciones y aprendizaje) | Sensor = mensaje del usuario; procesador = seguridad + modelo ML; secuencia de percepciones = memoria de 1 turno (`contexto_previo`) cuando pide aclaración; actuador = respuesta y probabilidades; aprendizaje = pestaña *Aprendizaje*. | `p07_inferencia.py`, `app.py`, `p09_reentrenamiento.py` |
| **Semana 04** | Metodología de desarrollo en etapas y ejemplo de análisis de sentimiento | Seguimos el ciclo ordenado: definición del problema, carga y limpieza de datos (`p02`–`p03`), comparación de modelos (`p05`–`p08`), evaluación (`p06`, `p10`) y despliegue web (`app.py`). | Todo `entrenamiento/` y `app.py` |
| **Semana 05** | Probabilidades que suman 1, incertidumbre y semilla fija (`random_state`) | El modelo devuelve probabilidades entre 0 y 1 que suman 100 % sobre las 5 emociones, usa esa incertidumbre para pedir contexto y fija `SEMILLA = 42` para que los resultados sean siempre reproducibles. | `p01_config.py`, `p07_inferencia.py` |
| **Semana 07** | Datos sintéticos cuando faltan datos reales y sistemas basados en reglas | Combinamos datos reales traducidos (`go_emotions_es_mt`) con datos sintéticos y un corpus curado de situaciones implícitas, separando siempre su procedencia en la columna `origen`. La capa de crisis usa reglas claras. | `p02_datos.py`, `p02b_generar_corpus_implicito.py`, `p04_seguridad.py` |
| **Semana 09** | Enfoque híbrido (reglas + ML) y preprocesamiento de texto (`unicodedata`, `re`, normalización) | Reglas fijas para seguridad + Machine Learning para emociones. Limpiamos tildes y signos con `unicodedata` y `re`, pero **conservamos las negaciones (`no`, `nunca`, `tampoco`)** y la `ñ` porque en emociones cambiarían todo el sentido. | `p03_preprocesamiento.py`, `p04_seguridad.py` |
| **Semana 11** | Aprendizaje supervisado, adaptación al cambio (como el filtro de spam), librerías de Python (`scikit-learn`, `NumPy`), mitigación de sesgos en 3 etapas y métricas (`Precision`, `Recall`, `F1-Score`) | 1) **Preprocesamiento:** 0 fugas, limpieza con `neg_` y corpus curado para quitar sesgos como `ayer → alegría`. 2) **Aprendizaje:** `class_weight="balanced"` y regularización `C=3.0`. 3) **Postprocesamiento:** umbral de abstención (pedir contexto). Además, ciclo adaptable de correcciones en la pestaña *Aprendizaje*. | `p02_datos.py`, `p03_preprocesamiento.py`, `p05_modelos.py`, `p06_metricas.py`, `p09_reentrenamiento.py` |
| **Semana 12** | Algoritmos de clasificación (Regresión Logística Multinomial con Softmax, Naive Bayes, SVM, métodos ensamblados), partición **Training / Validation / Testing** y matriz de confusión | Comparamos 9 modelos respetando estrictamente la separación entre entrenamiento, validación y test reservado. Usamos `LogisticRegression` con Softmax y matrices de confusión 5×5. | `p05_modelos.py`, `p06_metricas.py`, `p08_experimentos.py`, `p10_evaluar_test.py` |
| **Semana 14** | Reducción de dimensionalidad y Red Neuronal Perceptrón Multicapa (`MLPClassifier`) | Probamos `TruncatedSVD` (150 componentes, versión de PCA para matrices dispersas de texto) seguido de `MLPClassifier` (64 neuronas ocultas) y lo comparamos honestamente en validación contra la Regresión Logística. | `p05_modelos.py`, `p08_experimentos.py` |
